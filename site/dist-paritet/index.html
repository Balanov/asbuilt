The check nobody else does

          
Three numbers,
not two.

        

        
lspci compares a device with its own capability. That misses the case where the board or the firmware capped the slot, and it flags the case where a device misreports itself. asbuilt reads three numbers and compares all of them.

Verdict

          
Link running at half its capability

          
−50.0% of link bandwidth · 31.5 of 63.0 GB/s per direction

          
The endpoint supports Gen5 x16, the port allows Gen5 x16, and the negotiated link is Gen4 x16. Nothing in the operating system reports this. The link is up, the device works, and the cluster is quietly half as fast as the invoice says it should be.

Read, judge, prove

          
Three steps,
no daemon.

        

        
asbuilt has no database, no background agent, no telemetry and no configuration file. It runs when you ask it to, prints what it found, and exits with a code your pipeline can gate on.

      

      

        

          
01

          
Read

          
The kernel and the firmware. sysfs, procfs and the SMBIOS table, decoded against the DMTF specification, with every unreadable source reported instead of hidden.

          
asbuilt manifest > node.json

        

        

          
02

          
Judge

          
Thirty-three rules compare what the machine is against what it should be, and compute the bandwidth the configuration actually costs you.

          
asbuilt check

        

        

          
03

          
Prove

          
Diff two nodes, check a node against an expected profile, and fail a provisioning pipeline when a machine is not what was ordered.

          
asbuilt --profile node.json check --fail-on critical
